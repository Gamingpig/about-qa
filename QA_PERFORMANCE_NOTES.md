# QA Performance and Media Notes

- Mobile lyrics rendering previously kept requesting display-rate animation frames even when most DOM work was skipped. Touch and low-end devices now run the lyrics update at 30 fps; playback time still comes from the existing monotonic progress clock, and pending frames are cancelled on pause or page hiding.
- The default fill gradient previously let its final stops exceed 100%, which left browser-dependent clipped highlights at word completion. Its stops are now clamped and completed/held words switch to a solid fill. Character weights and DOM lookups now run only for character-level styles; punctuation weights are included in normalization so a word's timing ends at exactly 100%.
- The artist slideshow previously mixed album covers and unrelated sources into its image list and capped it at 12. It now combines stats.fm profile-image URLs with all distinct `ab676161` artist photos exposed by the public Spotify artist page, with no gallery cap. The Gus Jeffers page currently exposes 12 distinct profile-photo IDs; repeated image renditions are deduplicated. Album-cover IDs are excluded.
- Spotify's documented public artist API does not expose a complete historical photo archive. The extra current-profile photos are read through a public text-rendering proxy, so proxy availability and Spotify page markup remain external dependencies; this cannot promise every image Spotify has ever stored. Stale artist requests are ignored when the selected artist changes.
- Spotify playback is controlled outside this page, so the browser cannot read its audio sample clock. Lyrics/video timing is driven by polled playback-position snapshots plus a monotonic local clock, and canvas video elements are synchronized to each other. Sample-accurate audio-to-canvas synchronization cannot be promised through this integration; it would require an audio source/clock exposed to the page or an authorized playback integration that provides that timing.
