1. Der Durchbruch: Das Ende des manuellen Re-Syncs

ROOT CAUSE ANALYSIS & DIE NEUE AUTONOME PIPELINE

❌ Das Problem in früheren Versionen
  • Abbruch bei Overlay-Öffnung: Jedes Mal, wenn der Nutzer die Lyrics-Ansicht angetippt hat (toggleLyrics(true)), wurde force = true übergeben. Dadurch wurde currentFetchId inkrementiert und die bereits laufende Hintergrundabfrage sofort abgewürgt.
  • HTTP 429 als Dead-End gecacht: Wenn LRCLIB aufgrund schneller Titelwechsel mit Rate-Limit (429) antwortete, hat das alte System fälschlicherweise angenommen, der Song habe keine Lyrics (provider: 'none') und den Fallback-Screen mit dem Re-Sync-Button angezeigt.
  • Duration-Jitter: Durch die Übergabe der Spotify-Dauer an die API führten minimale Abweichungen von ±1 Sekunde zu 404-Fehlern und Kaskaden-Spam.
✅ Die Lösung im neuen Algorithmus (v24.222.0)
  • Non-Aborting Pipeline: toggleLyrics() und Standby-Wechsel laufen jetzt mit force = false. Laufende Requests werden nicht mehr abgebrochen, sondern warten harmonisch ab.
  • Instant Memory-Cache First: Vor jedem Netzwerkaufruf prüft das System den lokalen lyricsMemoryCache. Liegen Lyrics vor, werden sie in unter 1 ms gerendert.
  • Selbstheilender 429-Scheduler: Tritt ein HTTP 429 auf, merkt sich das System lrclibRateLimitedUntil und stößt vollautomatisch nach 2,5 Sekunden einen Hintergrund-Retry an (lrclibAutoRetryTimeout). Der Nutzer sieht niemals mehr einen Dead-End-Screen.
  • Dauer-Entkoppelte Primärabfrage: /api/get?track_name=...&artist_name=... wird primär ohne fehleranfällige Laufzeit-Restriktion abgefragt.
// Neuer Resilienz-Ablauf in toggleLyrics & fetchExternalLyrics
// 1. Sofortige Prüfung des Memory-Caches beim Öffnen
const cachedEntry = lyricsMemoryCache[cacheKey];
if (cachedEntry && cachedEntry.parsed && cachedEntry.parsed.length > 0) {
    parsedLyrics = cachedEntry.parsed;
    currentLyricsProvider = cachedEntry.provider;
    renderLyrics(); // Instant Render < 1ms
    return;
}

// 2. Schutz vor Abbruch laufender Fetches
if (isFetchingLyrics && !force) {
    console.log("[Lyrics] Abfrage für Track läuft bereits – kein Abbruch");
    return;
}

// 3. Rate-Limit Handhabung & Auto-Retry ohne Nutzer-Intervention
if (res.status === 429) {
    wasRateLimited = true;
    lrclibRateLimitedUntil = Date.now() + 2500;
    // Song NICHT als 'none' cachen, sondern Hintergrund-Wiederholung einplanen:
    clearTimeout(lrclibAutoRetryTimeout);
    lrclibAutoRetryTimeout = setTimeout(() => {
        fetchExternalLyrics(currentTrack, currentArtist, currentDuration, false);
    }, 2500);
    return;
}

2. Multi-DB-Erweiterung: Zukünftige Lyrics- & Metadatenbanken

PROVIDER-ORCHESTRIERUNG & KASKADIERTE REDUNDANZ

Um auch bei seltenen Songs, Remixes, Unplugged-Sessions oder Ausfällen externer Server maximale Verfügbarkeit zu garantieren, wurde die Lyrics-Engine modular auf eine kaskadierte Multi-Datenbank-Architektur umgestellt:

Tier 1: LRCLIB (High-Speed Primär-Engine)

Aktiv Live

Open-Source-Datenbank für millimetergenaue synchrone Songtexte (.lrc Format). Verwendet den offiziellen Header Lrclib-Client: AboutQA/1.0, um Cloudflare-Sperren zu umgehen.

Latenz: ~120ms

Tier 2: NetEase Cloud Music & Vercel Bridge

Vorbereitet & Integriert

Riesiger internationaler Musikkatalog für asiatische und europäische Releases. Dient als primärer Ausfall-Fallback, falls LRCLIB einen Song nicht indexiert hat.

Fallback Stufe 1

Tier 3: Sekundäre Provider (Genius, Musixmatch Bridge, stats.fm DB)

In Vorbereitung

Erweiterungsschnittstelle für Textmetadaten, Song-Annotations und Übersetzungen. Bei ungesyncten Songs schaltet das System nahtlos in den dynamischen Smart-Scroll-Modus.

Fallback Stufe 2

3. Datenschutz, DSGVO & Zero-PII Garantie

TRANSPARENZ FÜR ADMINS & RECHTSKONFORMITÄT

Sämtliche Abfragen an externe Songtext- und Musik-APIs (LRCLIB, stats.fm, Apple Music, Deezer) wurden nach dem Prinzip der vollständigen Datenminimierung (Privacy by Design) umgesetzt:

🔒 Keine Nutzeridentifikatoren

Es werden weder IP-Hashes noch Spotify-Benutzerkonten oder Tokens an Songtext-APIs weitergereicht.

🧼 Bereinigte Metadaten

Die Anfrage enthält ausschließlich den reinen Songtitel und Künstler (z. B. track_name & artist_name).

⚡ Volatile Caches

Alle Antworten verbleiben im flüchtigen Session-Speicher des Browsers und werden beim Schließen des Tabs gelöscht.

Die offizielle Datenschutzerklärung (privacy.html) wurde in allen 6 Sprachen mit Stand 15. Oktober 2026 aktualisiert und deckt die neuen Dienste lückenlos ab.
